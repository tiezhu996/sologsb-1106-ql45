# 木版年画刻版工序档案

## 项目简介

面向木版年画作坊的纯前端工序档案应用。它把画稿、分版、刻版、修版与套色印制过程串成可追溯的本地记录，便于刻工与印制管事按套色序号协作。

## Docker 一键启动

首次启动先复制环境配置，再构建并启动容器：

```bash
cp .env.example .env && docker compose up -d --build
```

停止服务可执行：

```bash
docker compose down
```

## 数据存储说明

数据全部写入浏览器 IndexedDB，不依赖后端服务。数据库名为 `gbwoodprint-db`，当前结构版本为 `3`。

- `version(1)` 建立画稿、版片、刻工、印制批次、工序节点五张表及常用查询索引。
- `version(2)` 为各表回填 `schemaRev: 2`，便于后续迁移识别数据结构。
- `version(3)` 新增「崩口修补复检」表 `repairs`（按 `draftId, blockId, status` 建索引），并把旧版片备注中写明的崩口/修补信息迁移成崩口档案。
- 首次创建数据库时通过 Dexie 的 `populate` 回调写入四类画稿、完整基础版片、四名刻工、印制批次、多条工序节点与崩口修补复检样例。
- 刷新页面不会丢失数据；清除浏览器站点数据会同时清除本地档案。

## 崩口修补复检流程

每块版片可登记多处崩口，每处写清位置、严重程度（轻 / 中 / 重）、登记人与日期，并按下列状态流转：

1. **待修**：登记崩口后，由修补师傅填写修补人、日期与修法（嵌木、补线、顺线复刀等）。
2. **待复检**：修补交活后进入待复检，必须由**另一名师傅**（不得本人验本人）看过刀口，确认不再崩线后才判「通过」。
3. **已放行**：复检通过即放行；存在未放行崩口的版片不能标记刻成。复检判「未过」则退回待修，可继续修补，历轮修补与复检记录全部留痕。

版片编排台按画稿集中汇总待修、待复检崩口数量；已放行记录可在版片工序时间线页顺着版片回看。崩口档案按画稿与版片隔离，切换画稿互不串档。

## 核心功能与路由表

| 路由 | 页面 | 主要能力 |
| --- | --- | --- |
| `/drafts` | 画稿总览 | 按题材与状态筛选，查看版片刻成进度和最近印制批次，内联新建画稿 |
| `/drafts/:id/blocks` | 版片编排台 | 按套色序号排列表格，指派刻工、校验序号，按画稿汇总待修/待复检崩口，登记崩口修补并经另一名师傅复检放行后方可标刻成 |
| `/blocks/:id/nodes` | 工序节点时间线 | 推进或回退工序节点，登记操作人、时间与耗时，并回看该版片的崩口修补复检档案 |
| `/batches` | 印制批次登记 | 登记纸张、颜料、印数，并逐版填写套色偏差 |
| `/carvers` | 刻工档与版片分布 | 按专长筛选，查看在刻版片数、节点平均耗时与当班分布 |
| 其它 | 画稿总览 | 已实现 history 路由到画稿总览的回退 |
